# Design note — Release 1.0.2 part 1: every Salesforce field, new registers, new sync targets

**Scope.** Owner decision (ADR 0215): this installation is the ADoF standby system for Salesforce and must hold **every Salesforce data
field**. The fields that are missing become normal fields of the records: entity property, column, sync-target field, API and DTO, record page,
edit form, report dataset and AR / EN labels. There is no custom-field feature. Inputs are the owner's export `docs/salesforce/Object Data.xlsx`
(44 objects, 1,385 fields, picklist values) and the review sheet `docs/salesforce/Salesforce-mapping-review.xlsx`. Read this note with
`docs/design/salesforce-sync.md`.

## 1. The checklist and the test that enforces it
- `docs/salesforce/adof-export.json` is the snapshot of the export: field shapes and picklist values, with no record data. It is generated
  by `python3 -I tools/salesforce/export_snapshot.py snapshot`.
- Every field has a category:
  - **system**: identity, created / modified, owner, currency. These belong to the sync engine.
  - **calculated**: formula and roll-up fields, recalculated here. Optionally the source value is kept where the record already has a
    field for it.
  - **data**: must be held.
- `python3 -I tools/salesforce/export_snapshot.py coverage` writes `docs/salesforce/field-coverage.md`, which lists every field as held,
  calculated, system or ignored with its reason.
- `python3 -I tools/salesforce/export_snapshot.py fields <Object>` lists the data fields of one object and whether each is held.
- `python3 -I tools/salesforce/export_snapshot.py values <Object> <Field> [<lookup type>]` prints the value map and the pack lookup values
  of a picklist. Codes are generated by `code_of`: lower-case ASCII slugs, or `v-<sha1>` for Arabic-only values.
- `tests/Strategy.UnitTests/Integration/ShippedPackCoversExportTests.cs` checks every exported object:
  - every pack object and field exists in Salesforce;
  - every data field is mapped, or ignored with a reason (`"Field__c: reason"`);
  - every picklist and multi-select is mapped as `picklist`, and every active value has a code.
- The fake org (`MockSalesforceOrg.AddExportedObjects`) describes the exported objects as Salesforce has them, so *Validate* and runs
  catch fields that do not exist.

## 2. Rules for a missing field
1. **Where it goes:** a property on the record that the Salesforce object maps to. When the record already has the meaning (the review sheet
   says "map to an existing field"), map it to that field; do not duplicate it.
2. **Types:**

   | Salesforce type | Here |
   |---|---|
   | Text / Text Area | `string` with `HasMaxLength` of the Salesforce length |
   | Long / Rich Text | `string` (`text`). Rich text is sanitised on output (DOMPurify) and the `htmlToText` transform is used only when the record shows plain text |
   | Date | `DateOnly` |
   | Date/Time | `DateTimeOffset` |
   | Number / Currency | `decimal` `numeric(18,2)` |
   | Percent | ratio `numeric(9,4)`, mapped with `percentToRatio` |
   | Checkbox | `bool` |
   | Picklist | lookup code (`string`, `HasMaxLength(100)`) of a **lookup type** |
   | Multi-select picklist | `List<string>` / jsonb of codes (`Codes`) |
   | Lookup(Department) | unit id (`Unit` field, pack `reference` with `referenceType: org.unit`) |
   | Lookup(Contact / User) | employee id (`Person`) |
   | Lookup(another object) | `Reference` to its sync target |

   Bilingual pairs (`…_Ar__c` / `…_En__c`, `Name` / `Name_En__c`) go to `*_ar` / `*_en`.
3. **Lookup types** are declared in code with **no values** (`AddLookupType(new LookupTypeDefinition(code, system, ar, en, []))`). The ADoF
   values live in the pack's `lookups` section (ADR 0216) and are added on import or upgrade. Picklists whose values drive fixed logic (stage,
   status, direction) keep their fixed codes and map through a value map to those codes.
4. **Display numbers** (`Name` auto-numbers) are labels (ADR 0220):
   - The **unique index on the number** is replaced by a non-unique index.
   - The sync field is declared with `.DisplayNumber(code, property, numberingFormat)`, so the local counter continues after the synced
     labels.
   - Identity is the internal GUID plus the Salesforce Id.
5. **Editable** (owner decision): the new fields are in the create / update commands, validators, DTOs, the record page (grouped sections)
   and the edit form or wizard, in AR / EN, shown only where the user may read them.
6. **Reports:** every new field is added to the module's dataset / report-type and record-feed definitions (`Reporting/`, `Feeds/`), and
   lookup fields carry `LookupType`.
7. **Migration:** one per module, `V102Part1`. The columns are nullable, or have a default for `bool`. There is no data loss and no raw SQL
   on business tables.
8. **Calculated fields** are not stored. When this system has no equivalent calculation, record it in the object's `ignore` with the reason
   `calculated in Salesforce; …` and list it in the phase summary's known gaps.

## 3. Request + record pairs (ADR 0218)
`BMS_Process__c`, `Central_Registry_of_Documents__c` and `Intellectual_Property_Registry__c` each hold a request and the registry record.
Two pack objects on the same source object, `{Id}` template:
1. `requests.request`, a custom writer in the Requests module: type, stage, status, subject, `source = sync`.
2. The registry record, with `requestId` → `requests.request` (the same Salesforce Id).

A hook links `Request.SubjectType` / `SubjectId`. The approval history comes from `ProcessInstance` (source history). Files go to the registry
record (mapping option `fileOwner`).
