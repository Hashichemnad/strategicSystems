# 0175 — Theme tests: screenshots, reflow, axe per theme and visual baselines

- **Status:** Accepted by the owner (11 Nov 2026), Phase 20 — amended at acceptance (CI job, below)
- **Context:** SPEC-ADDENDUM §C5: WCAG 2.1 AA in all three themes and both directions; no layout shift at 360 px; Playwright screenshots of
  every main screen in every theme × AR/EN × light/dark; visual regression baseline per theme.

## Decision
- `web/e2e/themes.spec.ts` (projects `ar` and `en`): the administrator allows choosing; Mariam picks each theme × mode through the API and
  walks eight main screens (launcher, app home, list, project record, wizard, My Work, executive dashboard, Settings → Appearance):
  screenshot at 1366 px (`docs/screenshots/phase-20/<lang>-<theme>-<mode>-<screen>.png`) and `scrollWidth ≤ clientWidth` at 360 px. It
  restores the original settings afterwards, so the rest of the suite runs in Classic as before.
- `web/e2e/a11y.spec.ts` gains a theme pass (Enterprise and Modern, light and dark: launcher, palette, app home, list, project record,
  Appearance); Classic is the existing audit.
- **Visual regression:** Playwright projects `visual-ar` / `visual-en` (`visual.spec.ts`, `toHaveScreenshot`) on deterministic screens — the
  UI kit (`main` only, no live counters) per theme × mode, and the app launcher in the workspace themes — per language: 12 tests,
  20 baselines in `web/e2e/visual.spec.ts-snapshots/`. Locally the projects exist only with `E2E_VISUAL=1` (opt-in).
- **Identical rendering everywhere:** the check always runs through `tools/visual-regression.sh`, which starts the browser in the
  Playwright image **pinned by digest** (`mcr.microsoft.com/playwright:v1.56.1-noble`, Chromium 1194 = `@playwright/test` 1.56.1) and
  installs the **product fonts** (IBM Plex Sans, IBM Plex Sans Arabic, Noto Kufi Arabic) into it from the locked npm packages — no network,
  no font drift. The host runs outside the container on a **fresh Development database** (`--network host`).
- **CI:** job *Visual regression (themes)* in `.github/workflows/ci.yml` runs the script on every pull request and push to `main`; the
  owner makes it a **required status check** of the protected branch (Settings → Branches / Rulesets). A missing baseline fails
  (`updateSnapshots: 'none'` unless `UPDATE_SNAPSHOTS` is set).
- **Updating the baselines** (after an intended visual change): start PostgreSQL, Mailpit and Gotenberg, build the SPA, run the host on an
  empty database (`docker compose -f deploy/docker-compose.yml up -d postgres gotenberg mailpit`, `npm run build`,
  `dotnet run --project src/Host/Strategy.Host`), then `UPDATE_SNAPSHOTS=1 tools/visual-regression.sh`, review the changed PNGs and commit
  them with the change. Never update baselines from a browser outside the container. When `@playwright/test` is upgraded, change the
  image digest in the script and the workflow in the same commit and regenerate every baseline.

## Consequences
- A visual change without new baselines fails the pull request; the job's artifact holds the expected / actual / diff images.
- The screenshot set (96 images per run) is regenerated by one command: `E2E_SCREENSHOTS=phase-20 npx playwright test e2e/themes.spec.ts`.
