# 0215 — The ADoF standby holds every Salesforce data field

- **Status:** Proposed (release 1.0.2) — owner decision, awaiting acceptance of the implementation
- **Context:** The owner's export of the Salesforce org (`docs/salesforce/Object Data.xlsx`: 44 objects, 1,385 fields, 1,188 picklist
  values) and the review sheet (`Salesforce-mapping-review.xlsx`) showed that the pack held only part of the data: 502 data fields were not
  mapped, 31 were mapped wrongly (picklists copied as text, multi-selects into single fields), and about 20 object names and 60 field names did
  not exist in Salesforce at all. These names came from the 1.0 source documents. An installation that is to take over when Salesforce is
  unavailable cannot lose data.

## Decision
- This installation is the **ADoF standby system for Salesforce**. It holds every Salesforce **data** field.
  - **System** fields (Id, owner, created / modified, currency) belong to the sync engine: identity, source dates and creator.
  - **Formula and roll-up** fields are recalculated here.
- Missing fields are added as **normal fields** of the records: column, entity, sync target, API, record page, edit form, report dataset and
  AR / EN labels. They are editable like the existing fields, so the records stay complete after a failover. There is no custom-field
  feature.
- **One checklist:**
  - `docs/salesforce/adof-export.json` is the export snapshot: shapes and picklist values, no record data. It is generated by
    `tools/salesforce/export_snapshot.py`.
  - `docs/salesforce/field-coverage.md` lists every field and how it is handled.
  - `ShippedPackCoversExportTests` fails when a pack object or field does not exist in Salesforce, when a data field is neither mapped nor
    ignored with a reason, or when a picklist is not mapped with a code for each active value.
- The fake Salesforce org of the tests and the demo describes the exported objects as Salesforce has them, so a query of an invented field
  fails in CI as it does in Salesforce.
- The rules for each new field are in `docs/design/standby-every-field.md` §2.

## Consequences
- Records gain many optional fields, about 600 across 11 systems. Nothing is organisation-specific in code: picklist values come from the
  pack (ADR 0216).
- A later change to the Salesforce org is caught by regenerating the snapshot and running the test.
