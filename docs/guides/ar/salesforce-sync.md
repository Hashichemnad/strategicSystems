# المزامنة الاحتياطية مع Salesforce: الإعداد والمراقبة والتحويل والعودة إلى الاحتياط

للمسؤولين (المرحلة 23 والإصدار 1.0.1، ملحق المتطلبات §G، القرارات 0200–0208 و0210–0214). الشاشات: **الإعدادات ← التكامل ← مزامنة Salesforce**.

ما دام Salesforce هو النظام **الأساسي**، يتلقى هذا النظام نسخة منتظمة **في اتجاه واحد** من بياناته (الإدارات، والمستخدمين بعد مطابقتهم
مع الموظفين، والفرق، والمشاريع وسائر الأنظمة، والملفات، وسجل الاعتمادات) ليتمكن من تولي العمل إذا تعذّر الوصول إلى Salesforce.
**لا يكتب هذا النظام في Salesforce أبداً**: لا يرسل الموصل إلا طلبات قراءة (ومهام *استعلام* Bulk API 2.0). وتكون السجلات المتزامنة
**للقراءة فقط** هنا ما دام Salesforce أساسياً. وبعد أي انقطاع يُعيد المستخدمون إدخال التغييرات التي تمت هنا في Salesforce يدوياً،
بالاستعانة بـ **تقرير تغييرات فترة الانقطاع**.

## 1. في Salesforce: مستخدم التكامل ومجموعة الصلاحيات والشهادة وتطبيق العميل الخارجي

يتطلب هذا الجزء مسؤول Salesforce. منذ إصدار Spring '26 لم يعد ممكناً في معظم المؤسسات إنشاء **تطبيق متصل (Connected App)** جديد:
استخدم **تطبيق عميل خارجي (External Client App)** (ويستمر عمل أي تطبيق متصل موجود بالإعدادات نفسها).

1. **مستخدم التكامل** — Setup ← Users ← New user:
   - **ترخيص المستخدم: *Salesforce Integration*** وملف **Minimum Access – API Only Integrations** (للواجهة البرمجية فقط، ولا يمكنه
     الدخول إلى الواجهة). لا تستخدم حساب شخص. يمكن للمؤسسات التي لا تملك هذا الترخيص استخدام ترخيص عادي مع ملف للواجهة البرمجية فقط.
   - ثم في صفحة المستخدم ← **Permission Set License Assignments** ← Edit ← اختر **Salesforce API Integration** (ترخيص مجموعة الصلاحيات
     الذي يتيح صلاحيات الكائنات لهذا الترخيص).
2. **مجموعة الصلاحيات** «Strategy standby sync — read only» — Setup ← Permission Sets ← New، **الترخيص: *Salesforce API Integration***:
   - صلاحيات النظام: **API Enabled**. صلاحية *View Setup and Configuration* **غير مطلوبة** (ولا يمكن منحها لهذا الترخيص): من دونها يرفض
     Salesforce مورد حدود الواجهة البرمجية `/limits`، فتقرأ المزامنة الاستهلاك من ترويسات ردود Salesforce (انظر §6).
   - إعدادات الكائنات: **Read** و**View All** (حتى لا تُخفي قواعد المشاركة سجلات) على **كل كائن متزامن**: `Department__c` و`User` و`Contact`
     و`Project_Team__c` و`Project_Team_Association__c` و`PMS_Project_Request__c` و`PMS_Project__c` و`PMS_Work_Plan__c` و`PMS_Project_Kpi__c`
     و`PMS_Project_Risk__c` و`PMS_Project_Stakeholder__c` و`PMS_Project_Planning_Item__c` و`PMS_Challenges_Constraints__c` و`PMS_Change_Request__c`
     و`PMS_Contract__c` و`PMS_Lesson_Learned__c` و`PMS_Team_Meeting__c`، وكائنات الأداء (`Org_Kpi_Goal__c` و`Org_Kpi_Measure__c` و`Org_Kpi_Process__c`)،
     و`Risk_Kpi_Relation__c`، وكائنات المخاطر والتدقيق وخطط الإجراءات التصحيحية والمقارنة المعيارية وسجل الوثائق والملكية الفكرية والمهام في مؤسستك.
   - صلاحيات الحقول: **Read** على **كل حقول** هذه الكائنات (الحقل الذي لا يستطيع المستخدم قراءته يعرضه *التحقق* على أنه «غير موجود»)،
     ومنها `Contact.Employee_Number__c` المستخدم لمطابقة جهات الاتصال مع الموظفين.
   - الملفات: امنح المستخدم الوصول إلى المكتبات أو السجلات التي يجب نسخ ملفاتها. سجل تغييرات الحقول: صلاحية قراءة كائنات `…__History`
     (وأبقِ *Track Field History* مفعلاً للكائنات التي تريد عرض سجلها في لوحة «سجل المصدر»).
   - لا تمنح أبداً *Create* أو *Edit* أو *Delete* أو *Modify All* أو *View All Data*: المزامنة تقرأ فقط.
   - **أسند** مجموعة الصلاحيات إلى مستخدم التكامل.
3. **الشهادة والمفتاح الخاص** (على جهاز المسؤول، لا على الخادم). باستخدام OpenSSL:
   ```bash
   openssl req -x509 -newkey rsa:2048 -sha256 -days 730 -nodes -keyout strategy-sync.key -out strategy-sync.crt -subj "/CN=Strategy standby sync"
   ```
   وإن لم يكن OpenSSL مثبتاً، فسطر واحد باستخدام Docker (يكتب الملفين في المجلد الحالي؛ في PowerShell استخدم `${PWD}` بدلاً من `$PWD`):
   ```bash
   docker run --rm -v "$PWD:/out" -w /out alpine/openssl req -x509 -newkey rsa:2048 -sha256 -days 730 -nodes -keyout strategy-sync.key -out strategy-sync.crt -subj "/CN=Strategy standby sync"
   ```
   يُرفع `strategy-sync.crt` إلى Salesforce (الخطوة 4)، ويُدخل `strategy-sync.key` (المفتاح الخاص بصيغة PEM) في هذا النظام في الخطوة 2.4 ثم
   يُحذف من الجهاز. تُرفض المفاتيح الأقل من 2048 بت.
4. **تطبيق العميل الخارجي** — Setup ← **External Client App Manager** ← **New External Client App**:
   - المعلومات الأساسية: الاسم (مثل *Strategy standby sync*)، وبريد جهة الاتصال، وحالة التوزيع **Local**.
   - **API (Enable OAuth Settings)**: فعّله؛ وعنوان الرجوع `https://localhost/unused` (لا يستخدمه تدفق JWT)؛ ونطاقات OAuth:
     **Manage user data via APIs (api)** و**Perform requests at any time (refresh_token, offline_access)**.
   - **Flow Enablement**: فعّل **Enable JWT Bearer Flow** وارفع `strategy-sync.crt`. أنشئ التطبيق.
   - تبويب **Policies** ← Edit ← سياسات OAuth: **Permitted users: Admin approved users are pre-authorized**، ثم **Select permission sets** ←
     أضف «Strategy standby sync — read only». احفظ.
   - تبويب **Settings** ← **OAuth Settings** ← **Consumer Key and Secret** (يطلب Salesforce رمز تحقق) ← انسخ **Consumer Key**.
     لا يُستخدم السر.
   - قد يستغرق التطبيق الجديد بضع دقائق قبل أن يقبل تسجيل الدخول.

## 2. في هذا النظام: الاتصال

1. الإعدادات ← التكامل ← **مزامنة Salesforce** ← **الاتصال**.
2. **عنوان تسجيل الدخول**: `https://login.salesforce.com` (الإنتاج) أو `https://test.salesforce.com` (بيئة الاختبار) أو عنوان My Domain. HTTPS فقط.
3. **مفتاح المستهلك** (من تطبيق العميل الخارجي، الخطوة 1.4)، و**اسم مستخدم** التكامل، و**إصدار الواجهة البرمجية** (الافتراضي `v62.0`).
4. **المفتاح الخاص**: الصق محتوى `strategy-sync.key` (PEM). يُخزَّن مشفراً ولا يُعرض مرة أخرى — تُعرض **بصمته** فقط لتقارنها بالشهادة.
   استبدله قبل انتهاء الشهادة (كرر الخطوة 1.3 وارفع الشهادة الجديدة إلى التطبيق أولاً).
5. **حد Bulk** (الافتراضي 2000): التغييرات الأكبر منه تُقرأ بـ Bulk API 2.0 والأصغر بـ REST. التحميل الأولي يستخدم Bulk API 2.0 دائماً.
6. **حزمة المطابقة**: *ADoF Salesforce* (مرفقة مع النظام).
7. **اختبار الاتصال**: يسجّل الدخول بطريقة JWT bearer ويقرأ حدود الواجهة البرمجية وقائمة الكائنات. عند الفشل يعرض تبويب الاتصال
   **ما أجاب به Salesforce**: رمز حالة HTTP، والطلب (مثل `POST /services/oauth2/token` أو `GET /limits` أو `GET /sobjects` أو استعلام)، ورمز
   خطأ Salesforce ورسالته — مثل `invalid_grant` *user hasn't approved this consumer* ← سياسات الخطوة 1.4 (المستخدمون المصرّح لهم مسبقاً،
   وإسناد مجموعة الصلاحيات). وتظهر التفاصيل نفسها في سجل التشغيل وتبويب الحالة وسجل الخادم (دون رموز وصول أو مفاتيح أو بيانات سجلات).
   ظهور *«الربط يعمل مع تنبيهات»* مع **INSUFFICIENT_ACCESS** أو **FUNCTIONALITY_NOT_ENABLED** على `GET /limits` متوقع مع ترخيص
   *Salesforce Integration*: تستمر المزامنة وتقرأ الاستهلاك من ترويسات الردود.

## 3. المطابقات (محرر المطابقة)

تطابق حزمة ADoF كل كائن في Salesforce مع نوع سجل هنا. الكائنات التي لم يكن مستخدم التكامل يراها عند إعداد الحزمة مُعلّمة **مبدئية** ومعطّلة.

1. تبويب **المطابقات** ← افتح كائناً. يعرض الجانب الأول **قائمة حقول Salesforce الحية** (الأنواع وقيم القوائم)، والجانب الآخر مطابقات
   الحقول: حقل المصدر ← حقل الهدف، والنوع (مباشر، قائمة ← رمز، مرجع ← سجل متزامن، شخص ← موظف، نوع السجل، قيمة ثابتة)، وجداول القيم،
   والتحويلات (إزالة المسافات، أحرف كبيرة/صغيرة، نسبة مئوية ← نسبة، التاريخ فقط، HTML ← نص، اقتطاع، نعم/لا)، والإلزامية.
2. وأيضاً: القيم الافتراضية للحقول الفارغة، وقائمة الحقول المتجاهلة، وشرط التصفية (SOQL)، وقالب المعرّف الخارجي (مثل
   `{Id}-{year:End_Date__c}` لـ «تقييم واحد لكل سنة»)، وترتيب التحميل (الأب قبل الابن).
3. **تحقّق**: يفحص كل حقل وقيمة قائمة مقابل الوصف الحي. لا يُفعّل الكائن إلا بعد نجاح التحقق، وأي تعديل يلغي التأكيد. وتعرض التحذيرات
   قيم القوائم الجديدة التي لا رمز لها بعد، والحقول المخصصة غير المطابقة وغير المتجاهلة.
4. **تصدير / استيراد** الحزمة (JSON) للاحتفاظ بنسخة أو نقلها بين التركيبات. لا تُصدَّر الأسرار ولا علامات آخر مزامنة.
5. **الأشخاص**: يُطابَق مستخدمو Salesforce وجهات الاتصال مع الموظفين الحاليين (ولا يُنشأ موظف). المستخدمون: البريد الإلكتروني ثم
   `EmployeeNumber` ثم `FederationIdentifier`. ولا تحتوي جهات الاتصال على أي من هذين الحقلين: تطابقها حزمة ADoF بالبريد ثم بالحقل المخصص
   `Employee_Number__c`. لا يُستعلم إلا عن الحقول الموجودة في الكائن؛ وحقل أشخاص مُعدّ غير موجود في الكائن يظهر تحذيراً عند *التحقق* ويُتخطّى.
   ويذهب غير المطابَقين إلى قائمة الاستثناءات. مستخدمو Salesforce يُعطَّلون ولا يُحذفون: يبقى المستخدم المعطّل مطابَقاً.
6. **القوائم إلى حقول رقمية** (مثل `PMS_Project_Risk__c.Probability_Level__c` و`Impact_Level__c`، وهما قائمتان بالقيم `1`–`5`، إلى الاحتمال
   والأثر الصحيحين لخطر المشروع): استخدم النوع **قائمة ← رمز** مع جدول قيم (`1` ← `1` … `5` ← `5`، أو تسمية ← رقم). تُحوَّل القيمة المطابَقة
   إلى نوع حقل الهدف (عدد صحيح، رقم، نسبة مئوية، نعم/لا، تاريخ). ويحذّر *التحقق* من قيم القائمة الفعّالة غير الموجودة في الجدول، ويرفض
   جدولاً يعطي قيمة غير رقمية لحقل رقمي؛ أما المطابقة «المباشرة» لقائمة إلى حقل رقمي فمرفوضة («لا يناسب»).
7. يفحص *التحقق* **كل حقل ستستعلم عنه المزامنة**، لا الحقول المطابَقة فقط: `Id`، وحقل تتبّع التغييرات (العلامة الزمنية)، وحقول قالب
   المعرّف الخارجي، وحقول الأشخاص، وللملفات وسجل الاعتمادات وسجل تغييرات الحقول حقولَ `ContentVersion` و`ContentDocumentLink` و`Attachment`
   و`ProcessInstance` و`ProcessInstanceStep` وكائن `…__History` (مع علاقاتها، مثل `Actor.Name`). ويُبلَّغ عن الحقل الناقص مع الكائن والغرض منه
   قبل أي تشغيل. ولا يُستعلم عن `IsDeleted` إلا حيث يوجد في الكائن (لا يوجد في User).

## 4. التحميل الكامل الأول

حمّل بهذا الترتيب حتى يتطابق الأشخاص والوحدات:

1. **الإدارات**: فعّل `department` وحده (بعد التحقق)، ثم **تفعيل** من تبويب الحالة (يتطلب نجاح اختبار الاتصال؛ يصبح الوضع **احتياطي**)، ثم
   **تحميل كامل**. تصبح إدارات Salesforce وأقسامها وحدات تنظيمية (ويصبح رمزها المختصر رمز الوحدة).
2. **الموظفون**: استورد الموظفين عبر **استيراد الهيكل التنظيمي** (نموذج الموظفين) في تلك الوحدات. يجب أن يكون **البريد الإلكتروني**
   و**الرقم الوظيفي** مطابقين لما في Salesforce (`Email` و`EmployeeNumber` للمستخدم، و`Email` و`Employee_Number__c` لجهة الاتصال)، وإلا فلن يتطابق الأشخاص.
3. **المستخدمون وجهات الاتصال**: تحقق من `user` و`contact` وفعّلهما، ثم شغّل مجدداً (تحميل كامل).
4. **كل ما عدا ذلك**: تحقق من بقية الكائنات وفعّلها ثم شغّل **تحميلاً كاملاً**: يقرأ كل كائن مفعّل بـ Bulk API 2.0 حسب ترتيب التحميل، ويعرض
   تبويب الحالة التقدم لكل كائن.
5. افتح **الاستثناءات** وعالج ما ظهر:
   - *قيمة غير مطابقة* ← **طابق القيمة** (تضيف القيمة ← الرمز إلى جدول قيم الحقل) فيُعاد معالجة السجل فوراً.
   - *مستخدم غير معروف* ← **طابق الشخص** (اختر الموظف) ثم تُعاد معالجة السجلات التي تشير إليه. وإذا كثر الأشخاص غير المعروفين لنقص
     الموظفين، فاستوردهم ثم استخدم **إعادة معالجة الكل** مع السبب *مستخدم غير معروف*: يُعالَج الأشخاص أولاً ثم كل سجل يشير إليهم. ويعيد
     كل تشغيل أيضاً محاولة هذه السجلات بعد مطابقة أشخاصها.
   - *الأب غير موجود* ← يُحل غالباً تلقائياً عند وصول الأب؛ وإلا فراجع مطابقة الأب.
   - *قيمة غير صالحة* / *حقل إلزامي فارغ* ← صحّح المطابقة (تحويل أو قيمة افتراضية) ثم **أعد المعالجة**.
6. إعادة التشغيل آمنة: تُطابَق السجلات بمعرّف Salesforce، فلا يُنشأ شيء مرتين.

## 5. الجدول الزمني

تبويب **الجدول**: كل N ساعات (من وقت محدد في اليوم)، أو يومياً في وقت محدد، أو أسبوعياً في أيام محددة — بتوقيت التركيبة، مع عرض
التشغيلات الخمسة القادمة. ويحدد حقل *متأخرة بعد* (بالدقائق) متى تُعدّ المزامنة متأخرة. **زامن الآن** يشغّل مزامنة تزايدية فوراً.
تقرأ المزامنة التزايدية السجلات المتغيرة منذ آخر تشغيل فقط (`SystemModstamp` مع تداخل 5 دقائق)، وتُعلَّم السجلات المحذوفة في Salesforce
بـ **«محذوف في Salesforce»** هنا ولا تُحذف أبداً.

## 6. المراقبة

- تبويب **الحالة**: الوضع، وآخر تشغيل (الحالة والمدة)، والتشغيل القادم، واستهلاك الواجهة البرمجية من الحد اليومي، والأعداد لكل كائن
  (أُنشئ، حُدّث، دون تغيير، حُذف، فشل، تعارض)، والاستثناءات المفتوحة.
- تبويب **التشغيلات**: السجل التاريخي وسجل كل تشغيل.
- **تنبيهات بريدية** (بالعربية والإنجليزية) لحاملي صلاحية *إدارة المزامنة*: عند فشل تشغيل، وعند تأخر المزامنة (مرة لكل فترة تأخر).
- **صفحة السلامة** (الإعدادات ← السلامة ← التكامل): مزامنة Salesforce سليمة / متأخرة / فاشلة / استثناءات / هذا النظام أساسي.
- يتوقف التشغيل إذا بقي أقل من 10% من طلبات الواجهة البرمجية اليومية (قابل للضبط)، ويُفحص ذلك قبل كل كائن. تأتي الأرقام من `/limits`،
  أو — إن لم يُسمح لمستخدم التكامل بقراءته (ترخيص *Salesforce Integration*) — من الترويسة `Sforce-Limit-Info: api-usage=used/max` التي
  يرسلها Salesforce مع كل رد؛ وعندها يذكر شريط الاستهلاك أنه «من ترويسات ردود Salesforce» ولا تظهر أعداد مهام Bulk.
- تعرض الأخطاء **ما أجاب به Salesforce** (رمز حالة HTTP، والطلب، ورمز الخطأ، والرسالة) تحت الرسالة المترجمة، في سجل التشغيل وتبويب
  الحالة؛ ويحتوي سجل الخادم على الحقول نفسها.

## 7. ما دام Salesforce أساسياً (الوضع الاحتياطي)

- تظهر السجلات المتزامنة بشارة **«متزامن من Salesforce — للقراءة فقط»**، ويُرفض أي تغيير عليها من كل القنوات (الشاشات وواجهة REST
  وMCP والاستيراد والمهام المجدولة) برسالة واضحة، ولا يمكن تقديمها للاعتماد أو اتخاذ قرار عليها.
- تُعلَّق المهام المجدولة والإشعارات الخاصة بأنظمة العمل (لا تذكيرات ولا رسائل مكررة)، وتبقى لوحات المؤشرات والتقارير متاحة.
- تعرض صفحة السجل **سجل الاعتمادات** و**سجل تغييرات الحقول** من Salesforce تحت *المراجع الخارجية ← سجل المصدر* (للعرض فقط).
- السجلات المنشأة هنا وغير الآتية من Salesforce تبقى قابلة للتعديل.

## 8. دليل التحويل — «اجعل هذا النظام أساسياً»

استخدمه فقط عندما يتعذر الوصول إلى Salesforce مدة تستوجب استمرار العمل هنا.

1. تأكد من الانقطاع مع مسؤول Salesforce واتفقا على وقت التحويل، وأبلغ المستخدمين.
2. الإعدادات ← التكامل ← مزامنة Salesforce ← **التحويل** ← **اجعل هذا النظام أساسياً**: أدخل **السبب** و**رمز التحقق** (تطبيق المصادقة
   أو *أرسل رمزاً بالبريد*). تحتاج صلاحية *التحويل* (مسؤول التكامل، والتحقق بخطوتين إلزامي).
3. ما يحدث: تتوقف المزامنة، وتُفتح السجلات للتعديل، وتعمل مسارات الاعتماد والمهام والإشعارات كالمعتاد، وتبدأ **فترة انقطاع**، وتأخذ
   السجلات التي كان اعتمادها معلقاً في Salesforce حالة **«مطلوب إعادة التقديم»** — يعيد صاحبها تقديمها هنا ويتخذ المعتمدون القرار هنا
   (ويبقى سجل اعتمادات Salesforce ظاهراً).
4. يستمر العمل هنا، ويُسجَّل كل تغيير في سجل التدقيق ويظهر في **تقرير تغييرات فترة الانقطاع** (تبويب التحويل) مجمّعاً حسب النظام والسجل،
   مع القيم السابقة ← الجديدة ومعرّف Salesforce.

## 9. دليل العودة إلى الوضع الاحتياطي

عندما يعود Salesforce متاحاً:

1. **أوقف** العمل الجديد هنا أثناء إعادة الإدخال (اتفق على وقت مع المستخدمين).
2. افتح **تقرير تغييرات فترة الانقطاع** و**صدّره** (Excel أو PDF، بالعربية أو الإنجليزية) وأعد إدخال التغييرات في Salesforce، وعلّم
   **أُعيد إدخاله** لكل سجل. السجلات المنشأة هنا ليس لها معرّف Salesforce: أنشئها في Salesforce.
3. **العودة إلى الوضع الاحتياطي** (يجب أن يكون التقرير قد صُدّر أو أُقرّ). تُستأنف المزامنة وتعود السجلات المتزامنة للقراءة فقط.
   وتبقى السجلات التي تغيّرت هنا أثناء الانقطاع محمية: إذا أرسل Salesforce نسخة أحدث منها تنتظر **كتعارض**.
4. **التعارضات**: اختر لكل سجل **الإبقاء على النسخة المحلية** (تُتجاهل نسخة Salesforce حتى إغلاق فترة الانقطاع — عندما لم يُعَد إدخال
   التغيير في Salesforce بعد) أو **اعتماد نسخة Salesforce** (تُطبق فوراً — عندما يحمل Salesforce البيانات الصحيحة الآن).
5. **أغلق فترة الانقطاع** عندما لا يبقى تعارض معلق. ومن بعدها يكون Salesforce هو المرجع لكل السجلات من جديد.
6. إذا تعطل Salesforce مرة أخرى قبل الإغلاق فاستخدم **اجعل هذا النظام أساسياً** مجدداً: تستمر فترة الانقطاع نفسها.

## 10. معلومات مفيدة

- لا تكتب المزامنة في Salesforce أبداً؛ ولا يحتاج مستخدم التكامل إلا صلاحيات القراءة.
- لا يظهر المفتاح الخاص ولا رموز الوصول ولا بيانات Salesforce في السجلات التقنية؛ وكل إجراء للمسؤول مسجّل في سجل التدقيق
  (`integration.sync.*`)، وكل تغيير متزامن مدقَّق بقناة **sync**.
- للانتقال إلى مؤسسة Salesforce أخرى: صدّر الحزمة، وغيّر الاتصال، وتحقق من كل كائن، ثم شغّل تحميلاً كاملاً.
- **الترقية من الإصدار 1.0.0** (إصدار الحزمة 1 ← 2): تستبدل الترقية مطابقات `user` و`contact` و`project-risk` في حزمة *ADoF Salesforce* إن لم
  تكن قد عدّلتها، فتصبح معطّلة حتى **تتحقق** منها وتفعّلها من جديد. أما المطابقة التي عدّلتها فتبقى كما هي (يذكرها سجل الخادم): طبّق
  الإصلاحات يدوياً (خيارات جهة الاتصال؛ الاحتمال والأثر كقوائم مع جدول قيم) أو أعد استيراد الحزمة المرفقة. وأعد معالجة استثناءات
  *مستخدم غير معروف* المفتوحة بعد التشغيل التالي.
