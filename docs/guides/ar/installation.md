# دليل التثبيت — نظام الاستراتيجية المتكامل 1.0

موجَّه إلى فريق تقنية المعلومات الذي يثبّت النظام على خوادم الجهة نفسها. يعمل كل شيء داخل شبكتكم؛ لا حاجة إلى مفتاح ترخيص ولا إلى
اتصال بالمورّد ولا إلى الإنترنت (باستثناء مزوّد الذكاء الاصطناعي الذي تختارونه، إن وُجد).

> مراجع للمشغّلين: [`deploy/README.md`](../../../deploy/README.md) (جميع النصوص البرمجية وخياراتها)،
> و[`deploy/linux/README.md`](../../../deploy/linux/README.md) (التثبيت دون Docker)، وسجل التحقق
> [`docs/operations/verification-1.0.md`](../../operations/verification-1.0.md).

## 1. ما الذي يُثبَّت

| المكوّن | وظيفته | أين يعمل |
|---|---|---|
| **التطبيق** (`strategy-app:1.0.0`) | تطبيق الويب وواجهة البرمجة وخادم MCP والمهام المجدولة — برنامج واحد | حاوية (أو خدمة Linux) |
| **PostgreSQL 16** | جميع البيانات، بما فيها مفاتيح تشفير الأسرار المخزّنة (حلقة مفاتيح Data Protection) | حاوية (أو خادم قواعد البيانات لديكم) |
| **Gotenberg 8** | تحويل المستندات إلى PDF مع تشكيل صحيح للنص العربي | حاوية |
| اختياري: ClamAV وMeilisearch وOllama | فحص المرفقات من الفيروسات، والبحث داخل المستندات، ونموذج ذكاء اصطناعي محلي | حاويات (`--profile antivirus` / `search` / `ai`) |

**الشبكات المعزولة أو المقيّدة.** على جهاز متصل: `docker save strategy-app:1.0.0 -o strategy-app-1.0.0.tar`، واحفظوا
`postgres:16-alpine` و`gotenberg/gotenberg:8` بالطريقة نفسها. على الخادم: `docker load -i …` لكل ملف، ثم ثبّتوا مع
`--image strategy-app-1.0.0.tar` (أدناه). عند تجاوز حدّ Docker Hub اضبطوا `REGISTRY_PREFIX=mirror.gcr.io/` (أو مرآة السجل لديكم)؛
وخلف وكيل يفحص TLS اجعلوا `BUILD_CA_FILE` يشير إلى حزمة شهادات الجهة (تُستخدم أثناء البناء فقط ولا تُحفظ في الصورة).

## 3. التثبيت باستخدام Docker (موصى به)

فكّوا مجلد الإصدار، مثلًا في `/opt/strategy` (‏Linux) أو `C:\strategy` (‏Windows)، ونفّذوا **أمرًا واحدًا** من داخل المجلد:

```bash
./deploy/install.sh
```
```powershell
powershell -ExecutionPolicy Bypass -File deploy\install.ps1
```

يقوم برنامج التثبيت بما يلي:
1. ينشئ الملف `deploy/.env` مع **كلمات مرور مولّدة** (تبقى في المرات اللاحقة؛ وتُرفض كلمات المرور الواردة في المثال)؛
2. يتحقق من أن المنافذ غير مشغولة (انظر §4)؛
3. يبني الصورة `strategy-app:1.0.0` — أو يحمّلها باستخدام `--image <archive>` / `-Image <archive>`؛
4. يشغّل PostgreSQL وGotenberg وخطوة `migrate` لمرة واحدة (تنشئ كائنات قاعدة البيانات بدور المالك وتمنح الصلاحيات لدور التشغيل)
   ثم التطبيق؛
5. ينتظر حتى يصبح التطبيق سليمًا ثم يطبع عنوانه و**رمز الإعداد لمرة واحدة**.

إعادة تشغيله آمنة: تبقى كلمات المرور والبيانات الحالية وتُحدَّث الحاويات في مكانها.

## 4. منافذ مشغولة مسبقًا

منفذ التطبيق وحده يمكن الوصول إليه من الشبكة. أما PostgreSQL وGotenberg فيُنشران على `127.0.0.1` فقط (للأدوات المحلية).

| المتغير | القيمة الافتراضية | يستخدمه |
|---|---|---|
| `APP_PORT` | 8080 | التطبيق (المستخدمون أو وكيل HTTPS) |
| `APP_BIND` | جميع العناوين | اضبطوه على `127.0.0.1` عندما يعمل وكيل HTTPS على الخادم نفسه |
| `POSTGRES_PORT` | 5432 | ‏PostgreSQL على 127.0.0.1 |
| `GOTENBERG_PORT` | 3000 | ‏Gotenberg على 127.0.0.1 |

إذا كان المنفذ مشغولًا يتوقف برنامج التثبيت **قبل تشغيل أي شيء** ويذكر المتغير الذي يجب تغييره:

```
  Port 8080 (APP_PORT, the application) is already in use on this machine.
  Choose a free port and run the installer again, for example:
      APP_PORT=8090 ./deploy/install.sh
```

في Windows: ‏`$env:APP_PORT = 8090; .\deploy\install.ps1`. تُحفظ المنافذ المختارة في `deploy/.env` فتستخدمها الأوامر اللاحقة أيضًا.
لمعرفة البرنامج الذي يشغل المنفذ: `sudo ss -ltnp 'sport = :8080'` (‏Linux) أو `Get-NetTCPConnection -LocalPort 8080` (‏Windows).

## 5. التشغيل الأول: معالج الإعداد

افتحوا `http://<server>:<APP_PORT>/setup` وأدخلوا رمز الإعداد الذي طبعه برنامج التثبيت. إذا فُقد، اطبعوا رمزًا جديدًا:

```bash
docker compose -f deploy/docker-compose.yml --profile app run --rm app --setup-token
```

**المرحلة الأولى (بالرمز):** ملف الجهة (الاسم بالعربية والإنجليزية، المنطقة الزمنية، العملة)، والهوية البصرية (اللون، ترويسة البريد
وتذييله)، واللغات (اللغة الافتراضية، التاريخ الهجري، الأرقام العربية الهندية) و**المسؤول الأول**. بعد ذلك ينتهي الرمز ولا يمكن لأحد
استخدام المعالج مجددًا.

**المرحلة الثانية (بعد تسجيل الدخول):** سجّلوا الدخول بحساب المسؤول وأعدّوا التحقق بخطوتين (إلزامي للمسؤولين). يتابع المعالج:
خادم البريد (مع رسالة اختبار)، ومزوّد تسجيل الدخول (اختياري — Entra ID / ADFS / الهوية الرقمية UAE Pass / SAML / LDAP)، ومزوّد الذكاء
الاصطناعي (اختياري ويمكن تخطيه)، وساعات العمل والعطلات، واستيراد الهيكل التنظيمي (نزّلوا القوالب، واملؤوا الوحدات ثم الموظفين،
وارفعوها)، والأنظمة المراد تفعيلها، و**بيانات تجريبية** اختيارية للعروض (يمكن إزالتها لاحقًا من *الإعدادات ← بيانات العرض التجريبي*).
يمكن تخطي أي خطوة وإنجازها لاحقًا من *الإعدادات*؛ ويبقى المعالج متاحًا في *الإعدادات ← معالج الإعداد* حتى تنهوه.

بديل بالأوامر (دون المعالج): إنشاء المسؤول من سطر الأوامر — تُقرأ كلمة المرور من الإدخال القياسي:

```bash
read -rsp 'Administrator password: ' P && echo
printf '%s' "$P" | docker compose -f deploy/docker-compose.yml --profile app run --rm -T app --create-admin --email admin@example.org --password-file /dev/stdin
unset P
```

## 6. ‏HTTPS (إلزامي في بيئة الإنتاج ولخادم MCP)

ضعوا وكيلًا عكسيًا بتشفير TLS أمام التطبيق. توجد تهيئة جاهزة لـ nginx في
[`deploy/nginx/strategy.conf`](../../../deploy/nginx/strategy.conf) (ترويسات التمرير، وWebSockets للإشعارات الحية، وحجم الرفع).
ثم اضبطوا في `deploy/.env` وأعيدوا تشغيل برنامج التثبيت:

```
FORWARDED_HEADERS_ENABLED=true
FORWARDED_HEADERS_PROXY=<عنوان IP للوكيل كما يراه التطبيق>
SECURE_COOKIES=true
APP_BIND=127.0.0.1          # عندما يعمل الوكيل على الخادم نفسه
```

استخدموا شهادة الجهة. يمكن لصفحة *الإعدادات ← صحة النظام* التنبيه قبل انتهاء الشهادة عندما يُربط ملفها ويُدرج في
`Health:CertificatePaths`.

## 7. النسخ الاحتياطي

```bash
./deploy/backup.sh                          # في Windows: .\deploy\backup.ps1
./deploy/backup.sh --output /srv/backups
```

يحتوي مجلد النسخة `backups/strategy-<version>-<UTC time>/` على قاعدة البيانات (**بما فيها مفاتيح تشفير** الأسرار المخزّنة ومفاتيح
تطبيقات المصادقة)، والملفات، و`deploy/.env`، وشهادة Data Protection الاختيارية، وعدد صفوف كل جدول، وقيم التحقق. يتوقف التطبيق بضع ثوانٍ
لتكون جميع الأجزاء من اللحظة نفسها (يتجنب الخيار `--online` التوقف). يحتوي المجلد على كلمات مرور ومفاتيح: انسخوه خارج الخادم واحموا
النسخة. جدولوه يوميًا، مثلًا باستخدام cron:

```
15 1 * * * cd /opt/strategy && ./deploy/backup.sh --output /srv/backups >> /var/log/strategy-backup.log 2>&1
```

عند استخدام تخزين ملفات متوافق مع S3، انسخوا الحاوية (bucket) احتياطيًا بأدوات نظام التخزين نفسه.

## 8. الاستعادة (مع التحقق)

```bash
./deploy/restore.sh backups/strategy-1.0.0-20261106T021500Z         # يطلب منكم كتابة RESTORE
```
في Windows: ‏`.\deploy\restore.ps1 -Backup <folder>`. يتحقق النص البرمجي من قيم التحقق **قبل** أي تغيير، ثم يستعيد قاعدة البيانات
والملفات، ويقارن **عدد صفوف كل جدول** بالنسخة، ويرقّي المخطط إن كانت النسخة أقدم، ويعيد منح صلاحيات دور التشغيل، و**يتحقق من سلسلة
التجزئة لسجل التدقيق**، ثم يشغّل التطبيق ويفحص سلامته. أي اختلاف يوقف الاستعادة. على خادم جديد: شغّلوا برنامج التثبيت أولًا ثم
الاستعادة (أضيفوا `--with-env` لاسترجاع ملف `deploy/.env` القديم).

## 9. الترقية

فكّوا الإصدار الجديد فوق المجلد القديم (مع الإبقاء على `deploy/.env`)، واقرؤوا ملاحظات الإصدار، ثم:

```bash
./deploy/upgrade.sh                         # في Windows: .\deploy\upgrade.ps1     دون اتصال: --image <archive>
```

يبني النص البرمجي الصورة الجديدة بينما يعمل الإصدار القديم، ثم يأخذ **نسخة ما قبل الترقية**، ويوقف التطبيق، ويطبّق الترحيلات بدور
المالك، ويعيد منح صلاحيات دور التشغيل، ويشغّل الإصدار الجديد ويفحص سلامته. إذا فشل أي شيء يطبع أمر التراجع، مثلًا:

```bash
APP_VERSION=0.17.0 ./deploy/restore.sh <pre-upgrade backup folder> --yes
```

بعد الترقية من إصدار سابق للإصدار 1.0: أصبحت التذكيرات والملخصات والتصعيدات المجدولة تعمل وفق جداولها — أبلغوا المستخدمين.

## 10. التثبيت دون Docker (خدمة Linux)

بديل مدعوم: بيئة تشغيل ‎.NET 10‎، وPostgreSQL 16، وGotenberg (حاوية أو برنامج)، واختياريًا Tesseract للتعرف الضوئي على النصوص
(`tesseract-ocr tesseract-ocr-ara tesseract-ocr-eng`)، ووحدة systemd ‏`deploy/systemd/strategy.service`، وnginx. التعليمات خطوة
بخطوة، بما فيها دورا قاعدة البيانات والترحيل الأول والنسخ الاحتياطي والاستعادة والترقية يدويًا:
[`deploy/linux/README.md`](../../../deploy/linux/README.md).

## 11. بعد التثبيت

* *الإعدادات ← صحة النظام* — قاعدة البيانات، والترحيلات، والمهام المجدولة، وصندوق الصادر، والبريد، والذكاء الاصطناعي، والتعرف الضوئي،
  والتخزين، ومساحة القرص، وانتهاء الشهادات، وسلسلة التدقيق، والإصدار. راجعوها بعد كل تثبيت واستعادة وترقية.
* *حول النظام* في قائمة المستخدم — الإصدار وملاحظات الإصدار.
* مهام المسؤول في [دليل المسؤول](administration.md)؛ وربط Claude أو أي عميل MCP آخر في [دليل MCP](mcp.md).

## 12. حل المشكلات

| العَرَض | ما العمل |
|---|---|
| برنامج التثبيت: «port … is already in use» | اختاروا منفذًا آخر (§4) |
| صفحة `/setup` تفيد بأن المعالج مغلق | يوجد مسؤول مسبقًا — سجّلوا الدخول أو استخدموا *نسيت كلمة المرور* |
| رُفض رمز الإعداد | تنتهي الرموز بعد 24 ساعة وبعد إعادة التشغيل؛ اطبعوا رمزًا جديدًا (§5) |
| ‏«Run --migrate first» من `--create-admin` | نفّذوا `docker compose -f deploy/docker-compose.yml --profile app run --rm migrate` ثم أعيدوا المحاولة |
| فشل بناء الصورة بسبب الشهادات | اضبطوا `BUILD_CA_FILE` على حزمة شهادات الوكيل |
| ‏Docker Hub ‏«too many requests» | اضبطوا `REGISTRY_PREFIX=mirror.gcr.io/` (أو مرآتكم) في `deploy/.env` |
| فشل إنشاء ملفات PDF | *الإعدادات ← صحة النظام* ← خدمة PDF؛ تحققوا من حاوية `gotenberg` (‏`docker compose … ps`) |
| لا تُرسل الرسائل | *الإعدادات ← خادم البريد* ← *إرسال رسالة اختبار*؛ و*الإعدادات ← صحة النظام* ← صندوق الصادر |
| السجلات | ‏`docker compose -f deploy/docker-compose.yml --profile app logs app` (‏JSON منظم؛ لا تُسجَّل الأسرار أبدًا) |
