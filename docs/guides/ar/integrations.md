# التكامل: جهات التكامل وتغذيات التحليلات والاستخراجات وإشعارات Webhook وربط Power BI

للمسؤولين ومطوري الأنظمة الأخرى (المرحلة 22، ملحق المتطلبات §F، القرارات 0190–0195).

## 1. إنشاء جهة تكامل (المسؤول)

1. **الإعدادات ← التكامل ← جهات التكامل ← جهة تكامل جديدة.**
2. سمّها باسم النظام الآخر (مثل «Power BI — مكتب الاستراتيجية»).
3. **طريقة المصادقة**: *مفتاح API* لـ Power BI وExcel وTableau وQlik والبرامج النصية؛ و*بيانات اعتماد العميل OAuth 2.0* للأنظمة التي تدعمها.
4. **الأنظمة المسموح بها** (وأنواع السجلات اختيارياً)، و**الوحدة التي تعمل بها الجهة** (تُستخدم في نطاق «الوحدة» و«الوحدة وما دونها» لأدوارها)،
   و**العناوين المسموح بها** (عنوان أو نطاق CIDR في كل سطر)، و**الطلبات في الدقيقة**، و**تاريخ الانتهاء**.
5. احفظ و**انسخ معرّف الجهة والمفتاح أو السر الآن** — يُعرضان مرة واحدة فقط.
6. **تبويب الصلاحيات**: حدد الأدوار التي تحملها الجهة. صلاحياتها ونطاق بياناتها يحددان ما تقرؤه، تماماً كما للموظف.
   أنشئ دوراً مخصصاً في الإعدادات ← الأدوار إذا لم يناسب أي دور قائم (مثل «قراءة المحفظة — كل الجهة»).
7. **تبويب بيانات الاعتماد**: *إصدار بيانات اعتماد جديدة* يدوّر المفتاح؛ ويمكن أن تتداخل مفاتيح API حتى 30 يوماً. و*إلغاء الجهة* يوقفها نهائياً.
8. **تبويب الاستخدام**: كل طلب والطلبات المرفوضة (العنوان، حد الطلبات، الانتهاء، الإلغاء) والصفوف المقروءة؛ وكل قراءة للتغذيات مسجلة أيضاً في سجل التدقيق (القناة `api`).

## 2. تغذيات OData للتحليلات

`https://<الخادم>/odata/v1/<النظام>` — خدمة OData v4 للقراءة فقط لكل نظام (`portfolio` و`kpi` و`risk` و`teams` و`requests` و`docreg`
و`ip` و`bench` و`cap` و`auditmgmt` و`tasks`). و`…/$metadata` يصف ما يحق لـ*هذه الجهة* قراءته.

- `$select` و`$filter` (`eq ne gt ge lt le and or not in contains startswith endswith`) و`$orderby` و`$top` و`$skip` و`$count=true`
  و`$expand` على علاقات نوع السجل (مع `$select` و`$filter` و`$orderby` و`$top` داخلها).
- الرموز موجودة دائماً؛ و`<الحقل>Label` يعطي التسمية بحسب `?lang=ar` أو `?lang=en`.
- تأتي النتائج الكبيرة على صفحات: اتبع `@odata.nextLink`.
- كل صف وكل صف مرتبط يُصفّى بحسب صلاحيات الجهة ونطاق بياناتها.

## 3. ربط Power BI (فحص يدوي)

1. Power BI Desktop ← **الحصول على البيانات ← موجز OData**.
2. العنوان: `https://<الخادم>/odata/v1/portfolio?lang=ar` ← موافق.
3. بيانات الاعتماد: **Basic** — اسم المستخدم = معرّف الجهة (`ic_…`)، وكلمة المرور = مفتاح API ‏(`sik_…`). طبّقها على مستوى الخادم.
4. في المتصفح: حدد مثلاً *Projects* و*Milestones* ← **تحميل**. العلاقة بين المشروع ومعالمه على `id` = `projectId`.
5. خدمة Power BI: انشر التقرير ثم اضبط بيانات Basic نفسها في إعدادات مصدر البيانات (تحتاج إلى بوابة بيانات محلية إذا كان الخادم غير متاح من الإنترنت)،
   وجدول التحديث.
6. رمز 401 بعد فترة: تغيّر المفتاح أو انتهى أو أُلغيت الجهة. ورمز 429: قلل عدد مرات التحديث أو ارفع حد الطلبات.

Power Query (المحرر المتقدم):

```
let
    Source = OData.Feed("https://<server>/odata/v1/portfolio", null, [Implementation = "2.0", Query = [lang = "ar"]]),
    Projects = Source{[Name = "Projects"]}[Data]
in
    Projects
```

يستخدم Excel ‏(البيانات ← الحصول على البيانات ← من موجز OData) وTableau ‏(موصل OData) وQlik ‏(موصل OData / REST) العنوان وبيانات Basic نفسها.

## 4. الاستخراجات المتزايدة (ETL)

- المتغيرة: `GET /api/v1/integration/extracts/<النظام>/<EntitySet>?changedSince=2026-11-01T00:00:00Z&format=json|csv&lang=ar`
- المحذوفة (الملغاة / المسحوبة / غير النشطة): `…/<EntitySet>/deleted?changedSince=…`
- صفحات بالمؤشر: أعد `nextCursor` في `cursor` ما دام `hasMore` صحيحاً؛ واحفظ `watermark` ليكون `changedSince` في التشغيل التالي. وفي CSV يأتي
  المؤشر وwatermark في الترويستين `X-Next-Cursor` و`X-Watermark`.
- التصدير المجدول (جهات التكامل ← تبويب *التصدير المجدول*) يكتب التغييرات في مجلد فرعي داخل `Integration__ExportRoot` الذي يحدده المشغّل
  (JSON أو CSV). زامن هذا المجلد مع SFTP أو S3 بأدوات المشغّل.

## 5. إشعارات Webhook

جهة التكامل ← **تبويب إشعارات Webhook ← اشتراك جديد**: عنوان وجهة HTTPS (تُرفض عناوين الخادم نفسه والعناوين المحلية للرابط وعناوين بيانات
السحابة الوصفية)، والأحداث، ثم انسخ **سر التوقيع** (يُعرض مرة واحدة). الكتالوج مع أمثلة الرسائل في بوابة المطورين.

كل تسليم طلب `POST` بمحتوى JSON ‏`{ id, type, occurredAt, system, resource: { type, id }, data }` والترويسات `X-Strategy-Event`
و`X-Strategy-Delivery` (لاستبعاد التكرار) و`X-Strategy-Timestamp` و`X-Strategy-Signature: v1=<hex HMAC-SHA256(السر, "<timestamp>.<body>")>`.
أجب برمز 2xx خلال 10 ثوانٍ؛ يُعاد إرسال الفاشل بعد 1 ثم 2 ثم 4 ثم 8 … دقائق (8 محاولات، والفاصل 6 ساعات على الأكثر)، ثم ينتقل إلى **قائمة
المتعذر تسليمها** (الإعدادات ← التكامل ← تسليم إشعارات Webhook) حيث يمكن **إعادة إرساله**. لا تتلقى الجهة إلا أحداث السجلات التي يحق لها قراءتها.

## 6. إعدادات المشغّل

| المتغير | المعنى |
|---|---|
| `Integration__ExportRoot` | مجلد التصدير المجدول (اربط وحدة تخزين) |
| `Integration__AllowHttpWebhooks` | `true` في بيئة التطوير فقط: يسمح بوجهات `http://` |
| `Outbound__AllowPrivateNetworks` | `false` يرفض وجهات Webhook على الشبكات الخاصة (ADR 0155) |
