# Version 1.0.1

Fixes to the **Salesforce standby sync** found when testing it against a real Salesforce sandbox.

## Fixed
- **Works with the "Salesforce Integration" licence.** That licence cannot have *View Setup and Configuration*, which Salesforce needs to
  report the API limits. The connection test and the runs now continue with a warning, and the daily API usage is read from the headers of
  Salesforce's normal answers; the sync still stops when less than 10 % of the daily requests remain.
- **Clear error details.** Instead of "Salesforce answered with an error", the Connection tab, the run log and the Status tab show what
  Salesforce answered: the HTTP status, the call (for example the API limits, the object list or a query), Salesforce's error code and its
  message. Tokens, keys and record data are never shown or stored.
- **Users and contacts sync.** The sync no longer asks Salesforce for fields an object does not have: users have no "deleted" flag (they are
  deactivated — and stay matched to their employee), and contacts have no employee number or Federation ID. Contacts are now matched to
  employees by e-mail, then by the custom field *Employee Number*. *Validate* checks every field a sync will read, so a missing field is
  reported before a run.
- **Project risk probability and impact** (picklists 1–5 in Salesforce) are mapped to numbers; picklist mappings can now fill number fields
  in general.
- **Unknown persons resolve in one go.** After importing the missing employees, *Re-process all* with the reason *Unknown user* matches the
  people first and then resolves every record that pointed at them; each run also retries them.
- Project risks failed to save with their Salesforce Id; they now sync.

## Upgrading from 1.0.0
The *ADoF Salesforce* mapping pack is upgraded automatically for the user, contact and project risk mappings you had not changed; validate
and enable them again (Settings → Integrations → Salesforce sync → Mappings). The guide *Salesforce standby sync* describes the new
Salesforce set-up (External Client App, permission set) and the load order.
